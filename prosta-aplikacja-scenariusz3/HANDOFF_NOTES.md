## Important Implementation Notes

### Security Considerations
⚠️ **XSS Prevention**:
- NEVER use `innerHTML` with user content
- Always use `textContent` or `createTextNode()`
- The `sanitizeHtml()` function must strip all tags

### localStorage Best Practices
- Always wrap in try-catch blocks
- Handle `QuotaExceededError` gracefully
- Validate data structure on read
- Consider data migration for version changes

### Auto-Save Implementation
- Use debounce delay of 1000ms (1 second)
- Show visual feedback ("Saving...", "Saved", "Error")
- Update timestamp on each save
- Handle conflicts if user switches notes quickly

### Performance Considerations
- Parse localStorage JSON only once on init
- Keep notes array in memory (appState)
- Use DocumentFragment for batch DOM updates
- Implement virtual scrolling if > 1000 notes (optional)

### Browser Compatibility
- Use `crypto.randomUUID()` (available in all modern browsers)
- Use ES6 modules (type="module" in script tag)
- All CSS features are widely supported
- No polyfills needed for target browsers

## Known Design Decisions

1. **No Framework**: Vanilla JavaScript only (as per requirements)
2. **localStorage Only**: No server, no cloud sync (MVP scope)
3. **Single-Page App**: No routing, all views in one page
4. **Auto-Save**: Enabled by default with 1s debounce
5. **Search**: Real-time filtering (no separate search page)
6. **Timestamps**: Human-readable format ("2 minutes ago")
7. **Empty States**: Helpful messages for new users
8. **Confirmation Modals**: Only for destructive actions (delete)

## Potential Challenges & Solutions

### Challenge 1: localStorage Size Limits
**Solution**: Monitor usage with `getStorageInfo()`, warn at 80%, prevent save at 100%

### Challenge 2: Concurrent Tabs
**Issue**: Two tabs editing same note
**Solution**: Document as known limitation (or implement storage events in Phase 5)

### Challenge 3: Lost Focus During Auto-Save
**Issue**: Cursor jumps when DOM updates during typing
**Solution**: Don't re-render the active editor during auto-save, only update the list item

### Challenge 4: Large Note Count Performance
**Issue**: Rendering 1000+ notes is slow
**Solution**: Implement virtual scrolling or pagination (Phase 5 enhancement)
